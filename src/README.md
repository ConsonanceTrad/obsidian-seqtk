# SeqTK 源码结构（重构版）

本目录为重构后的源码骨架。
核心意图：**数据传递 / 数据传递 / 视图渲染 解耦分离，单作者项目里每层保持"小到不需要文档也能找到"**。

- `p` 前缀数字只是为了审阅便利，确保新功能加入时不会更改排序，不代表功能优先级。
- 各层详细职责与边界判据见各层 md 文档
- `main.ts` 组合根内部的注册逻辑已交由 Register

## 分层总览

- Register
  - 负责接管插件的模块注册，防止对插件入口进行频繁删改或错配
  - 防止主入口代码规格膨胀
- ~~Types~~ 已弃用：各层级持有自己的常量和类型定义，公用常量存储于 Tools/Const 中
  - ~~对 节点文件类型、视图细分类型、传输数据类型 等的定义、约束、接口~~
  - ~~与类型推定相关的逻辑代码~~
- Tools
  - 存储公用常量
  - 无副作用的静态逻辑
- Settings
  - 设置面板 UI 与设置配置文件的读写方式
- Nodes
  - 节点类型、从属、允许行为、职能规范的定义
  - 节点数据传递规范
- Data
  - SQLite 的接入逻辑
  - 缓存、文件的规范操作逻辑
  - 读写的顺序编排
  - 数据和其他层的套接层逻辑
- Views
  - 渲染各视图本身、向 Pipe 套接层请求和传递操作数据
  - 将渲染进行注册和拆分，使重复渲染组件体验一致
- Render
  - 可复用渲染组件库，包括：
  - Struct —— 系列固定的结构，可以将其作为视图的一部分直接使用
  - Composition —— 面板的组件，一般是视图中的某一部分
